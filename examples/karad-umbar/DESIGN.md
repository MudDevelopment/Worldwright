# Architecture: the kingdom under the mountain

A node is a room, not a network service. The first nine rooms implement an entire clue → exploration → seal → discovery loop. The tenth connects it to the Ring Road. The complete map has ten districts of ten: Last Muster, Cisterns, Bell Foundry, Fungal Terraces, Liftworks, Archive, Salt Road, Royal Kilns, Deep Hospice, Crown Vault. Each has named landmarks; nine outer districts have a unique evidence site. The ring stays open even when a player guesses a seal incorrectly. The vault holds a child's cup rather than treasure: the discovery is who actually saved the city.

**Content versus runtime.** world.json is authoritative schema-v1 authored content; use the existing ReferenceGame, Look/Move/Say, authenticated room-scoped multiplayer, one authoritative world owner and the existing PostgreSQL commit/receipt path. No new protocol verbs, database schema, server fork, or background generator. No title matching in server logic. Keep all participants on one activated content digest.

**Procedure.** generate.cjs compiles a shared edition offline. From nine districts it selects two distinct witnesses in order, and assigns two different directional seals. With three directions there are 9 × 8 × 3 × 2 = 432 possible kingdom-wide assignments, plus the hand-authored introductory edition. The commission names the two actual landmarks and ring entrances; both clues, valid transitions, failure paths and ending are emitted together. Versioned SHA-256 labels, stable IDs and pinned artifact bytes prevent rerolls on reconnect. The generator produces editions, not independent personal quests on login. Players may cooperate, share or guess a solution. No globally consumed key can strand another player.

**Durability boundary.** The committed world contains the assignment and gate routes; character position provides a durable checkpoint in PostgreSQL mode. Room-local speech is live, not a persistent chat transcript. Reading the roll is the ending; it does not write a completed-quest badge or grant currency. Future personal commissions require an explicit game contract, persisted assigned targets/phase/instance and a unique character+instance reward in the same owner transaction. Prove retry, crash and simultaneous turn-ins before promising a reward.

**Verification.** test.cjs checks the base edition and 128 deterministic seeded editions: exactly 100 distinct IDs and titles, ten equal districts, valid exit labels and unique destinations, reachability from and back to entry, clues and seal routing. Then run the native validator, playtest and two-player restart recipe in README.md. This addition does not change engine or migrations, but it does change the repository source inventory: retain previous R2 evidence against its original revision.
